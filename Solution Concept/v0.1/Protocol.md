## Рамка проекта (зафиксировано как понимание на текущий момент)

**Проблема, которую решаем:**
Текущий ручной режим регистрации и ведения заявок в Google Docs приводит к следующим проблемам:
- диспетчера не справляются с объемом работ
- заявки и данные по ним могут быть потеряны
- возникают случаи нарушения условий SLA
- растет количество жалоб от клиентов

**Что будет считаться успешным внедрением:**
- все заявки ведутся в единой системе
- можно увидеть всю историю по заявкам
- время регистрации заявки уменьшилось
- введена система управления обратной связью, позволяющая классифицировать жалобы
- количество жалоб от клиентов перестало расти

**Границы (что входит / не входит):**

Входит: 
- создание веб-интерфейса для регистрации заявок представителями клиентов 
- создание веб-интерфейса для регистрации и ведения заявок сотрудниками бэк-офиса
- создание мобильной версии веб-приложения для работы с заявками выездными мастерами
- создание веб-интерфейса для руководителя сервисного направления
- введения системы управления обратной связью
- интеграция с CRM

Не входит:
- мобильное приложение 
- контроль актуальной информации по представителям клиентов, CRM - источник данных

## Подтверждено заказчиком
1. Диспетчеры продолжают фиксировать в системе заявки, которые приходят по email, телефону
2. Представители клиентов должны иметь возможность создавать заявку в системе самостоятельно
3. Выездные мастера должны иметь возможность создавать заявку самостоятельно
4. Сейчас диспетчеры не закреплены за клиентской базой, а обрабатывают весь входящий поток
5. Если диспетчер работал с клиентом, то нужно настроить переадресацию звонков и email данному диспетчеру
6. После создания заявки назначаются группы работ по заявке
7. В заявке перечислены группы работ, за каждой группой в системе закреплён ответственный мастер, который подтягивается в заявку автоматически
8. Ответственный мастер по работам назначает выездных мастеров по этим работам
9. Есть список выездных мастеров, который состоит из внутренних сотрудников компании и внешних подрядчиков
10. В первую очередь распределение работ идёт по внутренним сотрудникам компании, затем по внешним подрядчикам
11. Выездные мастера предварительно обзванивают клиента перед визитом, уточняют время визита и подробности по работам
12. Выездной мастер прикладывает фото по завершению своих работ
13. Выездной мастер может не завершить работы по заявке в один визит
14. Нужен чат диспетчеров с выездными мастерами внутри заявки
15. Нужен чат-бот для представителей клиентов внутри заявки
16. Должна быть эскалация по неисполненной в срок заявке руководителю сервисного отдела и ответственному мастеру
17. Необходимо ввести приоритезацию заявок
18. Необходимо добавить возможность делать связные заявки
19. Руководитель видит все заявки и всю историю по ним
20. Руководителю доступен дашборд со всеми заявками и фильтрами по ним
21. Все пользователи могут добавлять файлы к заявке
22. Прикладываемые к заявке файлы — это фото или pdf
23. При отсутствии связи внесённые изменения в заявку сохраняются локально и отображается сообщение об отсутствии связи — данные не отправлены
24. При восстановлении связи синхронизация с сервером автоматическая (если нельзя, то кнопка для повторной отправки)
25. Для входа в систему сотрудники используют корпоративный провайдер идентификации
26. Необходима настройка интеграции с CRM для поддержки актуальной информации по клиентской базе (сотрудники клиентов, контакты сотрудников клиентов, срок исполнения по клиенту)
27. Необходимо реализовать возможность отправки рекламной рассылки клиентам (смена стоимости услуг, новые услуги и т.д.)
28. Необходимо хранить историю заявок в течение 3 лет, по истечении срока хранения заявки могут быть удалены
29. Заявку можно отменить с определённым статусом, но нельзя удалить
30. На первом этапе внедрения веб-интерфейс для клиентов не нужен, нужна рабочая версия для сотрудников компании
31. Метрики: 30 заявок в день, сотни заявок в пиковый период, 120 пользователей в день, до 500 пользователей в пиковый период


## Не подтверждено / требует уточнения
1. Только клиент или диспетчер переводят заявку в закрытые
2. Исполнитель может изменить статус выполненных работ, на которые он назначен
3. Исполнитель может перевести свои работы в статус выполнены, если он приложил фото, в том числе заполненный бланк
4. В заявке указаны работы, у каждого вида работ есть ответственный, по всей видимости еще должен быть статус по этим работам
5. Нужно ли автоматизировать подбор возможных исполнителей по графику для ответственного мастера или это остается на нем
6. Что в случае если мастер не сделал работы за один визит, нужно ли согласование по времени визита, а если вдруг ему прибавилось срочных заявок
7. Отображение неотправленных заявок: предложены отдельная группировка, заметная плашка с количеством либо счётчик на плашке «Данные не отправлены»
8. Непонятно нужно ли работать диспетчеру с заявкой пока по ней ведутся выездные работы, нужно ли давать доступ на редактирование и нужно ли вообще поле комментарий диспетчера, а если оно изменилось, то его кто должен заметить, нужно ли уведомлять или что вообще
